# PDF Generation

Generate a PDF with maroto `v2` from Go code: install the module, build the document, generate
the bytes and persist or return them. This is the entry point of the `pdf-*` skill set — read it
first, then follow the links to the skill that covers the decision in front of you.

See also:
- [config.md](config.md) for every `config.NewBuilder()` option (page size, margins,
  fonts, metadata, protection, generation mode).
- [layout.md](layout.md) for the row/column grid, auto rows, cell styling, headers,
  footers and page breaks.
- [components.md](components.md) for text, images, barcodes, QR codes, data matrices,
  lines, checkboxes and signatures.
- [tables.md](tables.md) for tabular data (invoices, reports, catalogs).
- [testing.md](testing.md) for unit-testing the component tree and debugging layout.

## Instructions

### 1. Install

```bash
go get github.com/johnfercher/maroto/v2@latest
```

The module path is `github.com/johnfercher/maroto/v2` — the `/v2` suffix is part of every import
path. The consuming module must use a Go version at least as new as the `go` directive in
maroto's own [`go.mod`](../../go.mod) for the release being pinned.

### 2. Mental model

- A document is a tree: **pages → rows → columns → components**. Nothing is drawn until
  `Generate()` walks the tree.
- Width is a **grid** of `12` units by default (`WithMaxGridSize` changes it). A column spans
  `n` units; the columns of one row should sum to the grid size.
- Height is in **millimetres**. A row has a fixed height (`row.New(20)`) or an automatic one
  (`row.New()` / `AddAutoRow`) computed from its tallest column.
- Rows flow top-to-bottom. When a row doesn't fit on the current page, maroto starts a new page
  automatically, re-drawing the registered header and footer.
- Every public type is built through a constructor returning an interface (`core.Maroto`,
  `core.Row`, `core.Col`, `core.Component`, `core.Document`). Never construct the structs directly.

### 3. Standard program skeleton

Split **building** the document from **writing** it. The builder returns `core.Maroto` so it can
be unit-tested through `GetStructure()` without touching the filesystem (see
[testing.md](testing.md)):

```go
package main

import (
	"log"

	"github.com/johnfercher/maroto/v2"
	"github.com/johnfercher/maroto/v2/pkg/components/text"
	"github.com/johnfercher/maroto/v2/pkg/config"
	"github.com/johnfercher/maroto/v2/pkg/consts/align"
	"github.com/johnfercher/maroto/v2/pkg/consts/fontstyle"
	"github.com/johnfercher/maroto/v2/pkg/core"
	"github.com/johnfercher/maroto/v2/pkg/props"
)

func main() {
	m := GetMaroto()

	document, err := m.Generate()
	if err != nil {
		log.Fatal(err)
	}

	if err := document.Save("report.pdf"); err != nil {
		log.Fatal(err)
	}
}

// GetMaroto builds the document tree. It is the unit under test.
func GetMaroto() core.Maroto {
	cfg := config.NewBuilder().
		WithPageNumber().
		Build()

	m := maroto.New(cfg)

	m.AddRows(text.NewRow(12, "Monthly Report", props.Text{
		Size:  16,
		Style: fontstyle.Bold,
		Align: align.Center,
	}))

	m.AddRow(8,
		text.NewCol(6, "Generated by maroto"),
		text.NewCol(6, "October 2026", props.Text{Align: align.Right}),
	)

	return m
}
```

Rules that follow from the skeleton:
- `maroto.New()` takes an optional `*entity.Config`; omit it for A4 portrait, 10 mm margins
  (20 mm bottom), Arial 10 pt, 12-unit grid.
- Call `Generate()` **exactly once** per `core.Maroto` instance. A second `Generate()` (or a
  `GetStructure()` followed by `Generate()`) on the same instance appends an extra blank page,
  because each call closes the page being built. Build a fresh instance through the factory
  function whenever another output is needed.
- `m.RegisterHeader(...)` / `m.RegisterFooter(...)` must be called **before** the first
  `AddRow*` — see [layout.md §6](layout.md#6-header-and-footer).

### 4. Pick the right constructor

Every component package exposes the same four shapes. Pick by how much wrapping the surrounding
code already does:

| You already have…           | Use                                            | Returns          |
|-----------------------------|------------------------------------------------|------------------|
| a `col.New(n)` to fill      | `text.New(value, props...)`                    | `core.Component` |
| a row, need one column      | `text.NewCol(size, value, props...)`           | `core.Col`       |
| nothing, fixed-height row   | `text.NewRow(height, value, props...)`         | `core.Row`       |
| nothing, content-sized row  | `text.NewAutoRow(value, props...)`             | `core.Row`       |

`NewRow` / `NewAutoRow` create a single column spanning the whole grid. The same table applies to
`image`, `code`, `line`, `checkbox` and `signature` (constructor names per component are in
[components.md](components.md)).

Then attach them to the document:

| Method                              | When                                                  |
|-------------------------------------|-------------------------------------------------------|
| `m.AddRow(height, cols...)`         | One fixed-height row from columns; returns the row    |
| `m.AddAutoRow(cols...)`             | One row sized to its tallest column; returns the row  |
| `m.AddRows(rows...)`                | Pre-built rows (`row.New`, `text.NewRow`, `list.Build`) |
| `m.AddPages(pages...)`              | Force a page break and add whole `page.New().Add(...)` blocks |

### 5. Output options

`Generate()` returns `core.Document`:

| Method                     | Use for                                                      |
|----------------------------|--------------------------------------------------------------|
| `Save(path) error`         | Write the file (parent directory must exist)                 |
| `GetBytes() []byte`        | HTTP responses, object storage, e-mail attachments           |
| `GetBase64() string`       | JSON payloads                                                |
| `Merge(bytes []byte) error`| Append another PDF's pages to this one, in place             |
| `GetReport() *metrics.Report` | Timing/size metrics — **`nil` unless** the instance was wrapped in `maroto.NewMetricsDecorator` |

Serving over HTTP:

```go
func handler(w http.ResponseWriter, r *http.Request) {
	document, err := GetMaroto().Generate()
	if err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "application/pdf")
	w.Header().Set("Content-Disposition", `attachment; filename="report.pdf"`)
	_, _ = w.Write(document.GetBytes())
}
```

Combining independently generated documents (e.g. portrait + landscape sections):

```go
func mergeDocuments(first, second core.Document) ([]byte, error) {
	return merge.Bytes(first.GetBytes(), second.GetBytes())
}
```

### 6. Errors to handle

Only a few calls return errors; handle every one of them instead of discarding with `_`:

| Call                                  | Error cases                                                        |
|---------------------------------------|--------------------------------------------------------------------|
| `m.Generate()`                        | Provider failure; `maroto.ErrCannotGenerateInParallelMode` / `ErrCannotGenerateInLowMemoryMode` in those modes |
| `m.RegisterHeader(rows...)`           | `maroto.ErrHeaderHeightIsGreaterThanUsefulArea`                    |
| `m.RegisterFooter(rows...)`           | `maroto.ErrFooterHeightIsGreaterThanUsefulArea`                    |
| `list.Build(...)`                     | `list.ErrEmptyArray`, `list.ErrNilElementInArray`                  |
| `fontrepository.New()...Load()`       | `fontrepository.ErrCannotReadFile`                                 |
| `document.Save(path)`                 | `core.ErrCannotWriteFile`                                          |
| `document.Merge(bytes)` / `merge.Bytes` | `core.ErrCannotMergeBytes` / `merge.ErrCannotMergePDFs`          |

Components never return errors. A missing image file, an unparseable byte slice, or a barcode
that can't be encoded renders the literal text `could not load image` / `could not generate
barcode` in red **inside the cell** instead of failing `Generate()`. Validate inputs (file exists,
EAN has 12–13 digits) before building the tree if that matters.

### 8. Checklist before handing over generated code

1. `go build ./...` and `go vet ./...` pass.
2. The columns of every row sum to the grid size (default 12); no row relies on overflow.
3. Fixed row heights leave room for the text they hold: a line of `S` pt text is
   `S / 2.835` mm tall (10 pt ≈ 3.5 mm) plus `props.Text.Top`. Wrapped text that is taller than
   its row is **not clipped** — it draws over the next row. Use `AddAutoRow` when the length is
   unknown ([layout.md §3](layout.md#3-auto-rows)).
4. Header/footer registered before content; `Generate()` called once per instance.
5. Non-Latin text (CJK, Arabic, Cyrillic, Hebrew, …) uses a registered UTF-8 font
   ([config.md §5](config.md#5-fonts)); the built-in fonts only cover Latin-1 (cp1252).
6. The program was actually run once and produced a file of non-zero size; while iterating,
   `WithDebug(true)` draws every cell's border so misaligned columns are visible.
7. A `GetStructure()` fixture test exists when the document will be maintained
   ([testing.md](testing.md)).
