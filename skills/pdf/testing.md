# PDF Testing

Unit-test and debug maroto documents without opening a PDF viewer: assert the component tree with
`pkg/test`, keep output reproducible, and find layout problems quickly.

See also:
- [generation.md](generation.md) for the `GetMaroto() core.Maroto` factory these tests
  depend on.
- [layout.md](layout.md) for the height arithmetic to check when a test shows an
  unexpected page count.
- [unit-tests.md](../../.github/skills/unit-tests.md) when the code under test lives in **this** repository — its
  naming, AAA and `t.Parallel()` rules apply on top of what's here.

## Instructions

### 1. Make the document testable

Expose a factory that returns `core.Maroto` and takes the data as parameters; keep I/O
(`Generate`, `Save`, HTTP) outside it:

```go
func GetMaroto(items []lineItem) core.Maroto {
	m := maroto.New(config.NewBuilder().WithPageNumber().Build())
	addInvoiceTable(m, items)
	return m
}
```

`m.GetStructure()` returns the full tree (config, pages, rows, cols, components and the non-default
props of each) as a `*node.Node[core.Structure]` without rendering anything, so a test can run in
milliseconds and needs no fonts, images or filesystem.

Build a **new** instance per test and per `Generate()`: `GetStructure()` and `Generate()` both
close the page in progress, so calling one after the other on the same instance yields an extra
empty page.

### 2. Snapshot the tree with `pkg/test`

1. Create `.maroto.yml` next to `go.mod`:

   ```yaml
   test_path: "test/maroto/"
   ```

   `test.New(t)` walks up from the test's working directory until it finds `.maroto.yml`; hitting
   `go.mod` first fails the test with `found go.mod but not .maroto.yml`. Create the
   `test/maroto/` directory.

2. Write the test. On the first run use `Save` to create the fixture, then switch to `Equals`:

   ```go
   func TestGetMaroto(t *testing.T) {
   	t.Parallel()
   	// Arrange
   	items := []lineItem{{Description: "Widget", Qty: 2, UnitPrice: 9.5}}

   	// Act
   	sut := GetMaroto(items)

   	// Assert
   	test.New(t).Assert(sut.GetStructure()).Equals("invoice.json")
   }
   ```

   Fixture path is relative to `test_path`; subdirectories are fine (`"examples/invoice.json"`).

3. Commit the fixture. When the layout changes on purpose, regenerate it by temporarily replacing
   `Equals("invoice.json")` with `Save("invoice.json")`, running the test once, and switching
   back. Review the fixture diff like code: it shows exactly which rows, sizes and props changed.

Fixture contents: every node has `type` (`maroto`, `page`, `row`, `col`, `text`, `image`,
`barcode`, `qrcode`, `matrixcode`, `line`, `checkbox`, `signature`), `value` (row height, column
size, text/code value, image path), and `details` with only the **non-default** props. Default
props don't appear, so adding `Align: align.Left` explicitly does not change a fixture.

### 3. Assert specific facts without a fixture

Walk the tree for targeted assertions (page count, a row height, a value) when a full snapshot
would be noisy:

```go
func pageCount(m core.Maroto) int {
	return len(m.GetStructure().GetNexts())
}

func TestGetMaroto_PageCount(t *testing.T) {
	t.Parallel()
	// Arrange
	items := make([]lineItem, 100)

	// Act
	sut := GetMaroto(items)

	// Assert
	assert.Greater(t, pageCount(sut), 1)
}
```

`node.GetData()` gives the `core.Structure{Type, Value, Details}`; `node.GetNexts()` the children
(`node` is `github.com/johnfercher/go-tree/node`, already a dependency of maroto).

### 4. Test the real output when it matters

Snapshot tests don't exercise the renderer. For a smoke test of the bytes:

```go
func TestGetMaroto_Generate(t *testing.T) {
	t.Parallel()
	// Arrange
	sut := GetMaroto([]lineItem{{Description: "Widget", Qty: 1, UnitPrice: 1}})

	// Act
	document, err := sut.Generate()

	// Assert
	assert.NoError(t, err)
	assert.True(t, bytes.HasPrefix(document.GetBytes(), []byte("%PDF-")))
}
```

- Don't compare generated bytes against a golden file: the creation date in the PDF header
  changes every run unless the config pins it with `WithCreationDate(fixedTime)`, and even then
  gofpdf's output is not guaranteed byte-stable across versions.
- Tests that call `Generate()` with `image.NewFromFile*` need the asset path to resolve from the
  test's working directory (the package directory under `go test`). Prefer `NewFromBytes*` with
  `//go:embed` so tests and binaries agree.

### 5. Debug a layout

| Symptom                                       | Check                                                                               |
|-----------------------------------------------|-------------------------------------------------------------------------------------|
| Text drawn over the next row                  | Fixed row too short for wrapped text — size it ([layout.md §2](layout.md#2-rows--fixed-height-in-millimetres)) or use `AddAutoRow` |
| Columns misaligned / content off the right edge | Column sizes don't sum to the grid; `WithDebug(true)` shows every cell border       |
| Text or checkbox overlaps the row above       | Negative `Top` in an auto row shrinks the row ([components.md §2](components.md#2-text--pkgcomponentstext-propstext)); use it in fixed-height rows |
| Header appears mid-page                       | `RegisterHeader` called after content was added                                     |
| Unexpected blank last page                    | `Generate()`/`GetStructure()` called twice on one instance, or a spacer row pushed past the page |
| Characters replaced by blanks/garbage         | Non-cp1252 text with a built-in font — register a UTF-8 font ([config.md §5](config.md#5-fonts)) |
| `could not load image` in red                 | Wrong path/working directory or unsupported format (only PNG/JPEG)                  |
| `could not generate barcode` in red           | EAN value isn't 12–13 digits, or the string can't be encoded                        |
| Auto-row image height wrong                   | Missing `JustReferenceWidth: true` in `props.Rect`                                   |
| Row grows past page in auto mode              | A single auto row taller than the useful area — split the text into paragraphs      |

Tools:
- `config.NewBuilder().WithDebug(true)` — draws every row/column boundary. Toggle it through an
  environment variable or flag while iterating; never leave it on in production output.
- `maroto.NewMetricsDecorator(m)` — wrap the instance; `document.GetReport()` then lists time per
  `AddRow`/`Generate` and the file size (`report.String()` or `report.Save(path)`). Use it before
  switching generation modes ([config.md §8](config.md#8-generation-mode-performance)).
- `GetStructure()` printed as JSON (`test.New(t).Assert(...).Save(...)` or your own walk) is the
  fastest way to see how many pages were produced and which rows landed where.
- Open the file: `document.Save("out.pdf")` and inspect with any viewer, or `pdfcpu info out.pdf`
  / `pdftotext out.pdf -` for page count and text content on a headless machine.
